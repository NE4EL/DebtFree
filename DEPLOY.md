# Запуск DebtFree на другом компьютере (macOS)

Инструкция для запуска готового приложения через Docker. Устанавливать Python, Node.js и PostgreSQL не нужно: всё работает внутри контейнеров.

После запуска работают три контейнера:

| Контейнер | Что делает |
|-----------|------------|
| `frontend` | nginx: отдаёт интерфейс React и передаёт запросы `/api` в backend. Единственный, кто открыт наружу (порт 8080) |
| `backend` | FastAPI: API и расчёты. При каждом старте сам применяет миграции БД |
| `db` | PostgreSQL 16. Данные хранятся в томе Docker и сохраняются между перезапусками |

---

## 1. Что понадобится

- Mac на Apple Silicon (M1–M4) или Intel. Все образы собираются нативно под обе архитектуры, Rosetta не нужна.
- Около 3 ГБ свободного места и интернет для первой сборки.
- **Docker Desktop** и **git**.

### Установка Docker Desktop

1. Скачайте Docker Desktop с https://www.docker.com/products/docker-desktop/ — выберите вариант **Apple Chip** или **Intel Chip** (узнать свой: меню  → «Об этом Mac»).
   Если установлен Homebrew, можно одной командой: `brew install --cask docker`.
2. Перенесите Docker в «Программы» и запустите. Дождитесь, пока значок кита в строке меню перестанет анимироваться (Docker Desktop is running).
3. Проверьте в Терминале:

   ```bash
   docker --version
   docker compose version
   ```

### git

Обычно уже есть. Если команда `git --version` предлагает установить инструменты разработчика — согласитесь.

---

## 2. Получить проект

```bash
git clone https://github.com/NE4EL/DebtFree.git
cd DebtFree
```

Если проект передаётся архивом или папкой — просто перейдите в неё: `cd путь/к/DebtFree`. Папки `node_modules` и `.venv` копировать не нужно.

---

## 3. Настроить секреты

Создайте файл настроек из шаблона и сгенерируйте случайные пароли:

```bash
cp .env.example .env
sed -i '' "s/^POSTGRES_PASSWORD=.*/POSTGRES_PASSWORD=$(openssl rand -hex 16)/" .env
sed -i '' "s/^JWT_SECRET=.*/JWT_SECRET=$(openssl rand -hex 32)/" .env
```

Проверьте результат: `cat .env`. Должно получиться примерно так:

```ini
POSTGRES_PASSWORD=3f9c1b7e...      # 32 символа
JWT_SECRET=a81d0c4e...             # 64 символа
APP_PORT=8080
```

Важно:

- Файл `.env` содержит пароли — не добавляйте его в git (он уже в `.gitignore`) и не пересылайте.
- Пароль БД задаётся **один раз** при первом запуске. Если потом поменять `POSTGRES_PASSWORD`, backend не сможет подключиться (см. «Решение проблем»).
- Если пароль придумываете сами — только латинские буквы и цифры, он подставляется в адрес подключения к БД.

---

## 4. Запустить

```bash
docker compose up -d --build
```

Первая сборка занимает 3–5 минут, следующие запуски — секунды. Проверьте состояние:

```bash
docker compose ps
```

Все три контейнера должны быть в статусе `running` / `healthy`.

Откройте **http://localhost:8080**, нажмите «Регистрация», создайте пользователя — и можно работать. Готовых пользователей и данных в системе нет.

Дополнительно:

- http://localhost:8080/api/health — проверка работоспособности: `{"status":"ok","database":"ok"}`
- http://localhost:8080/docs — интерактивная документация API (Swagger)

---

## 5. Проверить тестами (по желанию)

```bash
docker compose --profile test run --rm tests
```

Запускаются тесты по плану тестирования T1–T9 из отчёта (включая контрольный пример 4.7), тесты API и миграций. В конце должна быть строка вида `86 passed` без `failed`. Тесты используют отдельную базу `debtfree_test` и не трогают данные приложения.

---

## 6. Повседневные команды

Все команды выполняются из папки проекта.

| Задача | Команда |
|--------|---------|
| Остановить (данные сохранятся) | `docker compose stop` |
| Запустить снова | `docker compose start` |
| Остановить и удалить контейнеры (данные сохранятся) | `docker compose down` |
| Посмотреть логи | `docker compose logs -f backend` (или `frontend`, `db`) |
| Обновить после `git pull` | `docker compose up -d --build` |
| **Удалить всё, включая данные БД** | `docker compose down -v` |

Docker Desktop должен быть запущен. Контейнеры перезапускаются сами после перезагрузки Mac, если Docker Desktop стартует при входе в систему (Settings → General → Start Docker Desktop when you sign in).

### Резервная копия базы

```bash
# сохранить
docker compose exec -T db pg_dump -U debtfree --clean --if-exists debtfree > backup.sql

# восстановить (текущие данные в базе будут заменены данными из копии)
docker compose exec -T db psql -U debtfree debtfree < backup.sql
```

## 7. Открыть с другого устройства в той же сети

Узнайте IP-адрес Mac:

```bash
ipconfig getifaddr en0
```

На телефоне или другом компьютере откройте `http://<этот-IP>:8080`. Если macOS спросит, разрешить ли входящие подключения для Docker, — разрешите.

## 8. Выкладка на сервер (продакшен)

На Linux-сервере шаги те же: установить Docker Engine с плагином Compose, клонировать проект, создать `.env` (в Linux `sed -i` без `''`), выполнить `docker compose up -d --build`. Дополнительно:

1. **HTTPS.** Приложение слушает обычный HTTP на `APP_PORT`. Поставьте перед ним обратный прокси с сертификатом (Caddy, Traefik или nginx + Let's Encrypt) и закройте порт 8080 от внешнего мира файрволом.
2. **Документация API.** Если `/docs` не должна быть публичной, добавьте в `.env` строку `DOCS_ENABLED=false`.
3. **Резервные копии.** Настройте регулярный `pg_dump` (см. выше) с хранением копий вне сервера.
4. **Секреты.** Используйте свои значения, не из этой инструкции. Смена `JWT_SECRET` разлогинит всех пользователей.

Что уже настроено для продакшена:

- backend работает в режиме `production` и не запустится со слабым `JWT_SECRET` (короче 32 символов);
- пароли хранятся в виде хеша bcrypt, вход по JWT-токену;
- схема БД создаётся и обновляется миграциями Alembic при старте backend;
- контейнеры запускаются не от root (backend) и перезапускаются автоматически при сбое;
- healthcheck для всех сервисов, frontend стартует только после готовности backend, backend — после готовности БД;
- наружу открыт только nginx; БД и backend доступны лишь внутри сети Docker;
- nginx сжимает ответы, кеширует статику сборки и добавляет базовые заголовки безопасности.

## 9. Решение проблем

**`Cannot connect to the Docker daemon`**
Docker Desktop не запущен. Откройте его и дождитесь, пока значок кита перестанет анимироваться.

**`required variable POSTGRES_PASSWORD is missing` / `Задайте POSTGRES_PASSWORD в файле .env`**
Нет файла `.env` или он не в папке проекта — выполните шаг 3.

**`Bind for 0.0.0.0:8080 failed: port is already allocated`**
Порт 8080 занят другой программой. Укажите в `.env` другой, например `APP_PORT=8081`, и снова выполните `docker compose up -d`. Порты 5000 и 7000 на macOS занимает AirPlay — их лучше не использовать.

**backend в статусе `unhealthy` или постоянно перезапускается**
Посмотрите причину: `docker compose logs backend`.

- `password authentication failed` — `POSTGRES_PASSWORD` в `.env` изменили после первого запуска. Верните прежний пароль или, если данные не нужны, пересоздайте базу: `docker compose down -v && docker compose up -d`.
- `В production задайте JWT_SECRET длиной не меньше 32 символов` — сгенерируйте секрет командой из шага 3.

**Тесты: `database "debtfree_test" does not exist`**
Тестовая база создаётся только при самом первом запуске БД. Создайте её вручную:

```bash
docker compose exec db createdb -U debtfree debtfree_test
```

**Сборка падает с ошибками сети (`npm ci`, `pip install`)**
Проверьте интернет/VPN и повторите `docker compose build --no-cache`.

**Сборка очень медленная или прерывается**
Docker Desktop → Settings → Resources: выделите не меньше 4 ГБ памяти.

**Изменения в коде не видны**
Пересоберите образы: `docker compose up -d --build`. Если браузер показывает старую версию — обновите страницу с ⌘⇧R.
